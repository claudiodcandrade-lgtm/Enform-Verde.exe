# V88.181 — captura efetiva do diagnóstico do EXE Windows (22/11/2026)

- No último build, o teste completo do EXE em pasta limpa expirou após 900 s. O runner localizou os arquivos de entrada/progresso, mas não registrou conteúdo útil; a causa do congelamento continua não identificada.
- O próximo gate encerra a árvore do processo no timeout, registra tamanho e data de cada arquivo, lê bytes diretamente, delimita o conteúdo impresso e copia diagnósticos para `$RUNNER_TEMP/enform_acceptance_diagnostics`.
- Um passo condicionado a falha do job envia esses arquivos como artefato de diagnóstico, mesmo quando os passos posteriores de checksum e pacote são ignorados.
- O teste de regressão valida a presença dessas garantias no workflow. Isso melhora a observabilidade; não comprova correção do travamento.
- Não disponibilizar o EXE como versão concluída até a aceitação real Tapajós em pasta limpa terminar e produzir o relatório no mesmo SHA. A candidata segue experimental e sem homologação científica de campo.
